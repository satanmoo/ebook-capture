# ebook-capture

[English](README.md) | **한국어**

**교보도서관** 앱이나 **Chrome 웹 뷰어**에서 전자책 페이지를 넘기며 한 장씩 캡처하고, 전부 PDF 하나로 저장하는 macOS 명령줄 도구입니다. 아이패드에서 읽고 필기할 때 유용해요.

> **개인 학습 용도로만 사용하세요.** 캡처한 책을 공유하거나 배포하는 것은 저작권 침해입니다.

## 요구사항

- macOS 14 (Sonoma) 이상
- App Store의 교보도서관 앱(Apple Silicon Mac) 또는 → 키로 페이지가 넘어가는 Chrome 웹 뷰어
- 터미널 앱 권한 (시스템 설정 › 개인정보 보호 및 보안)
  - **손쉬운 사용**(접근성): 페이지를 넘기는 → 키 입력
  - **화면 기록**: 페이지 캡처

## 설치

```bash
brew install satanmoo/tap/ebook-capture
```

업데이트할 때는 tap을 먼저 새로 받아야 해요. `brew upgrade`만 하면 새 버전이 아직 안 보일 수 있습니다.

```bash
brew update && brew upgrade ebook-capture
```

## 사용법

뷰어에서 책을 연 뒤 실행합니다.

```bash
ebook-capture -o linear-algebra --app 1
```

옵션 없이 `ebook-capture`만 실행하면 값을 하나씩 물어봅니다.

| 옵션 | 의미 |
|---|---|
| `-o, --output FILE` | 저장할 PDF. 이름만 쓰면 현재 폴더에 저장되고, 경로도 됩니다(`~/Documents/la`). `.pdf`가 없으면 붙이고 알려 줍니다. |
| `--pages N` | N장 찍고 멈춤. 생략하면 책 끝까지 찍습니다. 두 쪽 보기에서는 한 장에 두 쪽이 담기므로 N은 쪽수의 절반입니다. |
| `--app APP` | 교보도서관은 `1` / `library`, Chrome은 `2` / `chrome` |
| `--region select` / `--region "x y w h"` | 캡처 영역. 마우스로 드래그하거나 좌표로 지정. 생략하면 창 전체에서 `--margin`(기본 10)만큼 안쪽을 찍습니다. |
| `-f, --force` | 이미 있는 FILE을 묻지 않고 덮어씀 |
| `--resume` | 멈춘 FILE 캡처를 이어서 함 (아래 참고) |

캡처를 시작하기 전에 `Saving to: <경로>`를 보여줍니다. 파일이 이미 있으면 `Overwrite? [y/N]`로 물어보고, 터미널이 아닌 곳에서 실행했다면 `-f` 없이는 멈춥니다.

실행 중에는 페이지마다 뷰어를 맨 앞으로 가져와 → 키를 누르므로 **키보드와 마우스를 건드리지 말고, 다른 앱으로 전환하지 마세요.** 페이지가 바뀌고 화면이 멈추면 찍어요. 페이지가 늦게 뜨면 5초를 더 기다리고, 그래도 바뀌지 않으면 책 끝으로 보고 멈춥니다. 같은 페이지를 중복으로 저장하지 않아요.

끝나면(중간에 멈추거나 영역 선택을 취소해도) 소리가 나고, 실행했던 터미널이 결과와 함께 다시 앞으로 옵니다.

페이지 수를 다 채웠든, 책 끝에 닿았든, Ctrl-C로 멈췄든, 오류가 났든, 그때까지 찍은 페이지는 PDF로 저장됩니다. 캡처가 실패하면 알 수 있는 경우 이유도 알려 줘요(예: "You switched to WezTerm while capturing", "The Chrome window is no longer on screen").

### 멈춘 캡처 이어서 하기

Ctrl-C나 오류로 멈추면 찍은 페이지를 남겨 두니, 멈춘 곳부터 이어서 찍을 수 있어요.

```bash
ebook-capture -o linear-algebra --resume
```

처음 실행의 앱, 캡처 영역, 페이지 수를 그대로 쓰고, 끝나면 전체 페이지로 PDF를 다시 만듭니다. **이어서 하기 전까지 뷰어의 페이지를 그대로 두세요.** 다음 페이지를 → 키를 누른 횟수로 계산하기 때문에, 그사이 직접 페이지를 넘기거나 탭을 새로고침하면 페이지를 건너뛰거나 중복으로 찍어요. `--resume` 없이 같은 이름으로 실행하면 이어서 할지 물어보고(터미널에서 실행한 경우), 아니면 새로 시작합니다.

남겨 둔 페이지는 임시 폴더에 있어서 macOS가 며칠 뒤 지울 수 있어요. 새로 시작하면 지우지 않고 휴지통으로 옮깁니다.

### 캡처 영역 고르기

질문이 나오면 셋 중 하나를 고릅니다.

1. **마우스로 선택** (`--region select`): 화면이 어두워지면 ⌘⇧4처럼 페이지 위를 드래그해요. 전체 화면 뷰어 위에서도 됩니다. 뷰어가 아닌 창이 앞에 나왔다면(예: 전체 화면 뷰어 대신 다른 Chrome 창) 뷰어로 전환해서 거기서 드래그하세요. **드래그한 창이 캡처할 창**이 돼요. Esc를 누르면 취소됩니다.
2. **직접 입력** (`--region "x y w h"`): `x`, `y`, 너비, 높이를 입력해요. 좌표는 **Cmd+Shift+4**로 잽니다. 십자 커서 옆에 커서 위치가 표시되니, 페이지 왼쪽 위 모서리에 올려 `x`, `y`를 보고 오른쪽 아래 모서리까지 드래그해 너비와 높이를 확인하세요. Esc를 누르면 스크린샷 없이 취소돼요. 이 숫자는 뷰어가 있는 화면의 왼쪽 위 기준입니다.
3. **창 전체** (플래그로 실행할 때의 기본값): 뷰어 창에서 `--margin`만큼 안쪽

정한 영역은 다시 쓸 수 있게 `--region "x y w h"` 형식으로 출력해 줘요. 창을 조금 벗어난 영역은 창 안쪽으로 잘라서 찍고 알려 줍니다.

### Chrome

- 뷰어 탭을 가장 최근에 쓴 Chrome 창의 현재 탭으로 두고, 시작 전에 본문을 한 번 클릭하세요. 주소창에 포커스가 있으면 → 키로 페이지가 넘어가지 않습니다.
- 창 전체 캡처에는 탭 바와 주소창이 포함돼요. 본문만 찍으려면 마우스로 페이지를 선택하거나 전체 화면을 쓰세요.

## 화질: 레티나가 유리한 이유

ebook-capture는 책 파일을 읽지 않아요. 뷰어 창을 **앱이 화면에 그린 모습 그대로** 한 장씩 찍습니다. 그래서 캡처한 페이지는 화면에 보이는 페이지보다 선명해질 수 없어요.

macOS는 창과 글자의 크기를 *포인트* 단위로 정하고, 1포인트를 몇 픽셀로 그릴지는 화면마다 다릅니다.

| 화면 | 1포인트를 그리는 픽셀 | 같은 900 × 1000 pt 페이지를 찍으면 |
|---|---|---|
| 일반 모니터 (예: 1920 × 1080) | 1 × 1 | 900 × 1000 px |
| 레티나 (예: 맥북 내장 화면) | 2 × 2 | 1800 × 2000 px |

아이패드 화면은 긴 쪽이 2000픽셀이 넘어서, 1배로 찍은 페이지는 늘려서 보여주느라 흐릿하고 2배로 찍은 페이지는 선명해요. 이미지를 소프트웨어로 키워도 소용없습니다. 앱이 1배로 그린 것을 늘릴 뿐이니까요.

2배로 찍는 방법은 이렇습니다.

- **레티나 화면에서 찍기.** 맥북을 클램쉘 모드로 쓴다면 캡처할 때만 덮개를 열고 뷰어 창을 내장 화면으로 옮기세요.
- **외부 모니터를 HiDPI 모드로 쓰기.** BetterDisplay 같은 도구로 1080p 모니터를 2배로 그리게 할 수 있어요(화면에 보이는 크기는 같고, 앱이 2배의 픽셀로 그림).
- **4K 모니터**는 배율을 조정한 해상도(기본값)에서 이미 2배로 그립니다.

뷰어를 **전체 화면**(Ctrl+Cmd+F)으로 두면 제목 막대가 캡처에서 빠지고 페이지 자체도 커집니다.

## 개발

의존성 없는 Swift 패키지입니다. Xcode 또는 Command Line Tools(`xcode-select --install`)가 필요해요.

```bash
swift build
swift test
swift run ebook-capture --help
```

E2E 확인은 실제 앱을 조작하므로, 위 권한이 있는 터미널에서 실행하세요.

```bash
scripts/e2e.sh preview      # 자동: 생성한 책을 Preview로 열어 확인
scripts/e2e.sh app 1        # 교보도서관에 열린 책으로 확인 (Chrome은 2)
```
