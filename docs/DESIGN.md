# 설계

## 범위

- 대상 앱: **교보도서관**(Apple Silicon Mac에서 실행되는 아이패드 앱)과 **Chrome 웹 뷰어**
- 페이지 넘김: **→ 키**
- 결과물: 캡처한 페이지를 한 장씩 담은 PDF 하나

## 동작 순서

1. 옵션을 읽고, 빠진 값은 대화형으로 묻는다 (`Options.swift`, `Prompts.swift`)
2. 출력 파일이 이미 있으면 캡처를 시작하기 **전에** 덮어쓸지 정한다
3. 앱을 번들 ID로 찾아 맨 앞으로 가져오고, 맨 앞 창을 고른다 (`AppTarget.swift`, `Screen.swift`)
4. 캡처 영역을 정한다: 사용자가 준 영역(창이 있는 화면 기준) 또는 창 전체에서 여백만큼 안쪽 (`Region.swift`)
5. 페이지마다: 앱을 앞으로 → → 키 → 화면이 바뀌고 멈출 때까지 기다림 → 창 캡처를 잘라 PNG로 임시 폴더에 저장. 페이지 수를 채우거나, 책 끝에 닿거나, 중단·오류가 나면 멈춘다 (`CaptureLoop.swift`, `PageWaiter.swift`)
6. 찍은 PNG를 이름순으로 PDF 하나에 담고 임시 폴더를 지운다 (`CaptureSession.swift`, `PDFWriter.swift`)

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 언어와 의존성 | Swift 하나. ScreenCaptureKit(캡처), CGEvent(키 입력), CoreGraphics(PDF). 외부 의존성 없음 | 한 언어로 전체 흐름을 다루고, 설치할 것이 없게 |
| 배포 | Homebrew tap. Actions에서 버전을 입력하면 테스트, Intel + Apple Silicon 공용 실행 파일, GitHub Release, tap의 formula가 함께 갱신됨. 버전은 코드에 두지 않고 릴리스 빌드에서 기록 ([RELEASING.md](RELEASING.md)) | 사용자가 빌드나 버전을 직접 관리하지 않게. brew로 받은 파일은 공증 없이 실행됨 |
| 앱 식별 | 번들 ID (`kr.co.kyobobook.KEL`, `com.google.Chrome`) | 교보도서관은 표시 이름(`교보도서관`)과 프로세스 이름(`KEL`)이 다르고, 이름은 시스템 언어와 한글 NFC/NFD 차이로 어긋날 수 있음. Chrome PWA(`com.google.Chrome.app.*`)는 번들 ID가 달라 섞이지 않음 |
| 앱 앞으로 가져오기 | `open -b <번들 ID>` (Launch Services) | `NSRunningApplication.activate`는 CLI 프로세스에서 거부될 수 있음 |
| 페이지 넘김 | 매 페이지 앱을 앞으로 가져온 뒤 CGEvent로 → 키 | 창이 뒤에 있으면 키가 무시됨 (아래 확인 결과) |
| 캡처 | 앱의 맨 앞 창만 ScreenCaptureKit으로 찍고 영역만큼 잘라냄 | 알림 창 등 다른 창이 위에 떠도 섞이지 않음. 화면 배율(레티나 2배)이 그대로 반영됨 |
| 넘김 대기 | 고정 대기 대신, 다시 찍은 이미지의 픽셀이 이전 페이지와 **달라지고** 한 번 더 찍어 **같아지면**(렌더링 완료) 저장. 한 번에 최대 5초(`EBOOK_CAPTURE_PAGE_TIMEOUT`) | 로딩이 느릴 때 같은 페이지가 중복으로 찍히지 않게 |
| 책 끝 | 5초 안에 안 바뀌면 키를 다시 누르지 않고 5초 더 기다림. 그래도 같으면 책 끝으로 보고 중복 페이지 없이 멈춤. `--pages`는 생략 가능(책 끝까지) | 키를 다시 누르면 늦게 뜬 페이지를 건너뛸 수 있음. 두 쪽 보기처럼 넘김 횟수를 계산하기 어려운 경우에도 책 끝에서 멈춤. 교보도서관은 마지막 페이지에서 → 키를 누르면 "마지막 페이지 입니다" 안내창이 떠서 이 화면이 한 장 더 저장됨 |
| 캡처 영역 좌표 | **앱 창이 있는 화면의 왼쪽 위 기준**. 생략하면 창 전체에서 `--margin`(기본 10) 안쪽 | ⌘⇧4가 보여주는 숫자를 그대로 쓸 수 있게. 외부 모니터가 주 화면이고 맥북 내장 화면에서 캡처해도 어긋나지 않음 |
| 출력 경로 `-o` | 이름 또는 경로, 실행 폴더 기준. 상위 폴더가 없거나 폴더를 지정하면 오류. 표준 출력(`-`)은 지원 안 함 | curl, gcc, pandoc 등 일반 CLI의 `-o` 관례 |
| `.pdf` 확장자 | 없으면 붙이고 알림 | 관례(그대로 씀)와 다르지만, 확장자가 없으면 Finder와 아이패드 필기 앱이 PDF로 인식하지 못함 |
| 기존 파일 | ffmpeg 방식: 터미널이면 `[y/N]`로 묻고, 자동 실행이면 오류. `-f`로 강제 | 캡처는 몇 분씩 걸려서 조용히 덮어쓰면 이전 결과를 잃을 수 있음 |
| 임시 폴더 | `$TMPDIR/ebook-capture/<파일 이름>/`. 시작할 때 남아 있으면 **휴지통으로 옮김**(옮길 수 없으면 멈추고 위치를 알려 줌) | 바탕화면을 어지럽히지 않고, 이전 실행의 PNG가 섞이지 않게. 실패한 실행의 유일한 사본일 수 있어서 지우지 않음 |
| 중단과 오류 | Ctrl-C는 플래그만 세우고 루프가 다음 확인 시점에 멈춤. 캡처 오류도 루프가 받아서, **어떻게 끝나든 찍은 페이지까지 PDF로 만듦**. 종료 코드는 정상 0, Ctrl-C 130, 오류 1 | 파일을 쓰는 도중에 죽지 않게. 수백 쪽을 찍다 오류가 나도 결과를 잃지 않게 |
| 루프 구조 | 페이지 루프(`CaptureLoop.swift`)는 화면 접근을 클로저로 받아서, 책 끝·중단·오류 규칙을 단위 테스트로 확인 | 실제 캡처는 권한이 필요해서 자동 테스트가 어려움 |
| PDF 생성 | CoreGraphics PDF 컨텍스트에 한 장씩 그림. 임시 파일에 쓴 뒤 옮김 | 메모리가 페이지 수와 무관하게 일정함 (100쪽 기준 약 60MB). 실패해도 반쯤 만든 PDF가 남지 않음 |
| Chrome 탭 지정 | 주소로 탭을 찾지 않음. 실행 시 안내 문구로 사용자가 준비 | 주소 매칭은 특정 사이트에만 맞춰짐 |
| 전제 | 앱이 OS 화면 캡처를 막지 않았기 때문에 동작함. 이를 우회하지 않음 | 앱이 창을 캡처 제외(`NSWindow.sharingType = .none`)로 설정하면 어떤 방식으로 찍어도 검은 화면 |

## 확인 결과 (2026-09-26, macOS 26.6)

대상 창을 Finder 뒤로 보낸 상태에서 시험했다.

| 대상 | 가려진 창 캡처 (ScreenCaptureKit) | 창이 뒤에 있을 때 → 키 (`CGEvent.postToPid`) |
|---|---|---|
| Preview | 됨 | 안 넘어감 |
| 교보도서관 | 됨 | 안 넘어감 |
| Chrome (웹 PDF 뷰어) | 됨 | 안 넘어감 |

- 결론: 페이지를 넘기려면 매번 창을 앞으로 가져와야 한다. 캡처 중에는 컴퓨터를 쓸 수 없다.
- macOS 26에서는 앱마다 메뉴 막대가 layer 0의 가로로 긴 창(예: 1920×30)으로 잡힌다. `CGWindowListCopyWindowInfo`로 창을 고를 때 크기(200×200 이상)로 거른다.

## 화질

캡처 해상도는 화면 배율을 따른다. 1배 외부 모니터(1920×1080)에서 교보도서관 한 페이지는 약 940×1030픽셀이고, 레티나(2배) 화면에서는 가로세로 2배로 찍힌다. 전체 화면으로 찍으면 제목 막대가 빠지고 페이지도 커진다. 캡처 크기를 억지로 늘려도 앱이 1배로 그린 것을 늘릴 뿐이라 선명해지지 않는다.
